# Эксперимент: прозрачная проверка

## Вопрос и метод

Проверяется техническая пригодность DeepSeek для предложения оценки и замечаний по одной рубрике при сохранении решения за преподавателем, а не педагогическая польза. Задание: объяснить смену дня и ночи. Три критерия оцениваются каждый от 0 до 2: вращение Земли, освещённая и неосвещённая стороны, ясность. Подготовлены восемь обычных ответов разного качества и четыре краевых: пустой, инструкция атакующего, HTML/скрипт и провокация выдуманной цитаты.

Оператор выбирает ответ и явно нажимает кнопку вызова. Backend отправляет фиксированные задание, рубрику и ответ в DeepSeek; модель и ключ задаются окружением, по умолчанию модель `deepseek-v4-pro`. Сервер проверяет три целочисленных балла 0–2, структуру замечаний и точное вхождение непустой цитаты в исходный ответ. Общие замечания с пустой цитатой допустимы. Ответ и ошибки выводятся как текст. Только предложение, прошедшее проверку, можно принять или отклонить; решение хранится в памяти и не публикуется. При повторном вызове решение сбрасывается. Есть максимум 15 попыток за процесс, без повторов; запрос ограничен фиксированным набором ответов и размером HTTP-тела, ответ модели — 800 токенами и 4096 символами. Сетевые ошибки и некорректный JSON явно отображаются и записываются в отчёт.

## Воспроизведение проверок

Обязательная среда проверок объявлена в `prototype.yaml`: Compose, файл `experiments/4dbf92b6-c89e-4eed-b092-ebc593ff5ddb/check.compose.yaml`, сервис `checks`. Нужны Docker Engine и Docker Compose; Python на хосте не нужен. Образ `python:3.12-alpine` предоставляет Python и стандартную библиотеку. При первой загрузке образа нужен доступ к реестру; сами проверки выполняются без внешней сети, без ключа API, от UID 10001 с репозиторием только для чтения.

Из корня репозитория одноразовый запуск, который завершает и удаляет проверочный контейнер:

```sh
docker compose -f experiments/4dbf92b6-c89e-4eed-b092-ebc593ff5ddb/check.compose.yaml run --rm -T --no-deps checks python3 -m unittest discover -s experiments/4dbf92b6-c89e-4eed-b092-ebc593ff5ddb/demo -p 'test_*.py' -v
```

Команда из manifest выполняется из `/workspace` внутри сервиса `checks`:

```sh
python3 -m unittest discover -s experiments/4dbf92b6-c89e-4eed-b092-ebc593ff5ddb/demo -p 'test_*.py' -v
```

Проверки используют подмену внешнего API, поднимают временный локальный HTTP-сервер и завершают его. Они проверяют данные, валидацию, запрет решения без валидного предложения, отсутствие неявного вызова, лимит, ошибки и безопасный способ вставки текста. Это не результаты DeepSeek. Проверки добавлены после реализации; искусственный предварительный RED не заявляется.

В этой среде разработки та же команда unittest выполнена на доступном локальном Python с `PYTHONDONTWRITEBYTECODE=1`: пять тестов, `OK`. Команда `docker compose -f experiments/4dbf92b6-c89e-4eed-b092-ebc593ff5ddb/check.compose.yaml config --quiet` также завершилась успешно. Это локальные проверки разработчика, не свидетельство исполнения Conductor или контейнера.

Две предыдущие обязательные проверки завершились с кодом 127: на проверочном хосте отсутствовали сначала `python`, затем `python3`. Это ошибки среды воспроизведения, а не отрицательные результаты гипотезы. Вместо очередной замены имени команды manifest теперь явно задаёт контейнер с Python. Одноразовая команда Compose выше была запущена здесь и завершилась с кодом 1 до старта контейнера: Docker daemon недоступен (`/var/run/docker.sock` отсутствует). Поэтому исполнение проверок в контейнере и сборка образа демо в этой среде не проверены. Такая неисправность запуска является ошибкой воспроизведения, а не научным результатом.

## Необязательный локальный запуск

```sh
cd experiments/4dbf92b6-c89e-4eed-b092-ebc593ff5ddb/demo
docker build -t transparent-review .
docker run --rm -p 8080:8080 -e DEEPSEEK_API_KEY -e DEEPSEEK_MODEL=deepseek-v4-pro transparent-review
```

Открыть `http://localhost:8080/`; остановить контейнер после работы. Для живого эксперимента оператор после публикации задаёт ключ через окружение контейнера и нажимает кнопку отдельно для каждого ответа. Скачать JSON-отчёт можно по ссылке в интерфейсе. Не указывайте ключ в командной строке или отчёте. Без ключа живой эксперимент помечен как не выполненный; отсутствие ключа не расходует лимит. Отчёт содержит метку fake-проверок, живые результаты, ошибки валидации и решения, но не включает ключ.

## Результаты, проблемы и ограничения

Гипотеза **не определена**: реальных запросов в рамках разработки не выполнялось; пригодность модели и полезность замечаний не измерены. Fake-проверки демонстрируют только поведение прототипа. Публикация и визуальная проверка в браузере не выполнялись; доступность, узкие экраны и реальная доступность выбранной модели остаются непроверенными. API может вернуть ошибку или JSON в неподдерживаемом формате; автоматического исправления и повторов нет. Данные, счётчик и решения теряются при перезапуске, лимит относится к одному процессу контейнера. Это демонстрационный однопользовательский сервис без системы учётных записей; он не предназначен для реальных ученических данных или промышленной эксплуатации. Набор мал и синтетичен, оценка полезности замечаний требует отдельного исследования. Kafka, PostgreSQL и Keycloak намеренно отсутствуют.
